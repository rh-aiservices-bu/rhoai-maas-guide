= Request Deep Dive: Pod-by-Pod Tracing

This page traces an inference request through every pod in the {rhoai} 3.5 {maas} stack. Use it to understand where to look when debugging, what each component does to the request, and which `oc` commands to run.

TIP: For an animated walkthrough of these flows, see the link:{attachmentsdir}/flow.html[RHOAI 3.5 Flow Visualizer^].

== Envoy Filter Chain (Inside the Gateway)

The `maas-default-gateway` Envoy proxy in `openshift-ingress` processes every request through this filter chain:

image::deepdive-filter-chain.svg[Envoy filter chain - 4 stages inside the Gateway,width=100%]

[cols="1,3,3,3", options="header"]
|===
| Order | Filter | Pod / Mechanism | What It Does

| *①*
| `ext_proc` (IPP Pre)
| `payload-pre-processing`
| Extracts model name from body into `X-Gateway-Model-Name` header. Runs BEFORE auth so Kuadrant can use the header for per-model policy matching.

| *②*
| `wasm` (Kuadrant)
| WasmPlugin CR (in-process)
| Auth via Authorino (gRPC), rate limiting via Limitador (gRPC). Uses `X-Gateway-Model-Name` for route-level policy enforcement.

| *③*
| `ext_proc` (IPP Post)
| `payload-processing`
| Header guarding, usage enforcement, provider resolution, API format translation, credential injection. Runs AFTER auth completes.

| *④*
| `router`
| (built-in)
| Routes the mutated request to the upstream - external provider API or on-cluster InferencePool/InferenceService.
|===

[source,bash]
----
# View the EnvoyFilter that configures the two-stage IPP
oc get envoyfilter payload-processing -n openshift-ingress -o yaml

# View the Kuadrant WasmPlugin
oc get wasmplugin -n openshift-ingress -o yaml

# View all filters on the gateway
oc get envoyfilters -n openshift-ingress
----

== Namespace Map

Every component lives in a specific namespace. Here is the full layout for RHOAI 3.5:

++++
<div style="overflow-x:auto;max-width:100%">
<img src="_images/deepdive-namespace-map.svg" alt="RHOAI 3.5 namespace map" style="min-width:1800px;width:100%" />
</div>
++++

[cols="2,3,3", options="header"]
|===
| Namespace | Components | Purpose

| `openshift-ingress`
| maas-default-gateway (Envoy), payload-pre-processing, payload-processing, istiod, kube-auth-proxy, router-default
| Gateway, IPP ext_proc pods, Istio control plane

| `redhat-ai-gateway-infra`
| maas-api, maas-api-key-cleanup (CronJob)
| API key management (moved from redhat-ods-applications in 3.5)

| `redhat-ods-applications`
| maas-controller, maas-ui, postgres
| MaaS controller, UI, PostgreSQL database

| `kuadrant-system`
| authorino, limitador-limitador
| Auth server, rate limit server

| `models-as-a-service`
| MaaSAuthPolicy, MaaSSubscription CRs
| User-facing access control and quota definitions

| `ai-tenants`
| AITenant CRs
| Multi-tenancy configuration

| _model namespace_ (e.g., `llm`)
| vLLM pods, MaaSModelRef, TokenRateLimitPolicy, LLMInferenceService
| Model serving workloads

| _external-models namespace_
| ExternalProvider, ExternalModel CRs
| Third-party API proxy configuration
|===

[source,bash]
----
# Quick view of all MaaS-related pods across namespaces
oc get pods -n openshift-ingress -l app.kubernetes.io/part-of=maas 2>/dev/null; \
oc get pods -n redhat-ai-gateway-infra; \
oc get pods -n redhat-ods-applications | grep -E 'maas|postgres'; \
oc get pods -n kuadrant-system
----

== Pod-by-Pod Request Trace

=== External Model Request (e.g., Anthropic)

++++
<div style="overflow-x:auto;max-width:100%">
<img src="_images/deepdive-external-model.svg" alt="External model request sequence" style="min-width:1970px;width:100%" />
</div>
++++

[cols="1,2,2,3,3", options="header"]
|===
| Step | Pod | Namespace | What Happens | Debug Command

| 1
| _client_
| -
| Sends `POST /v1/chat/completions` with `Authorization: Bearer sk-oai-...`
| `curl -v https://maas.$\{CLUSTER_DOMAIN}/v1/chat/completions ...`

| 2-4
| `payload-pre-processing`
| `openshift-ingress`
| Parses JSON body, extracts `model` field, sets `X-Gateway-Model-Name` header. Resolves model type.
| `oc logs -n openshift-ingress deploy/payload-pre-processing -f`

| 5-6
| `maas-default-gateway` (Wasm)
| `openshift-ingress`
| Kuadrant WasmPlugin triggers auth-service action
| `oc logs -n openshift-ingress deploy/maas-default-gateway-istio -c istio-proxy -f`

| 7
| `authorino`
| `kuadrant-system`
| Receives gRPC call from Wasm shim. Calls MaaS API to validate the `sk-oai-*` key.
| `oc logs -n kuadrant-system deploy/authorino -f`

| 8-9
| `maas-api`
| `redhat-ai-gateway-infra`
| Looks up key hash in PostgreSQL. Returns `{valid, userId, groups, subscription}`. Injects `X-MaaS-Username` and `X-MaaS-Subscription` headers.
| `oc logs -n redhat-ai-gateway-infra deploy/maas-api -f`

| 10
| `limitador-limitador`
| `kuadrant-system`
| Receives gRPC call from Wasm shim. Checks token quota for the subscription.
| `oc logs -n kuadrant-system deploy/limitador-limitador -f`

| 11-17
| `payload-processing`
| `openshift-ingress`
| Runs post-processing plugins in order: maas-headers-guard, stream-usage-enforcer, model-provider-resolver (resolves ExternalModel CRD), api-translation (OpenAI to Anthropic format), apikey-injection (injects provider key from Secret).
| `oc logs -n openshift-ingress deploy/payload-processing -f`

| 18-19
| `maas-default-gateway` (router)
| `openshift-ingress`
| Routes mutated request to `https://api.anthropic.com/v1/messages`
| `oc logs -n openshift-ingress deploy/maas-default-gateway-istio -c istio-proxy -f`

| 20
| _Anthropic API_
| -
| Processes request, returns Anthropic Messages format response
| -

| 21-22
| `payload-processing`
| `openshift-ingress`
| Response plugins: api-translation converts Anthropic response back to OpenAI format
| `oc logs -n openshift-ingress deploy/payload-processing -f`

| 23-25
| `maas-default-gateway` (Wasm)
| `openshift-ingress`
| Kuadrant Wasm reads `usage.total_tokens` from response body. Reports consumed tokens to Limitador via gRPC.
| `oc logs -n openshift-ingress deploy/maas-default-gateway-istio -c istio-proxy -f`

| 26
| _client_
| -
| Receives OpenAI-format response regardless of which provider was used
| -
|===

=== Internal Model Request (P/D Disaggregated)

++++
<div style="overflow-x:auto;max-width:100%">
<img src="_images/deepdive-pd-disaggregated.svg" alt="Internal Model P/D disaggregated sequence" style="min-width:1450px;width:100%" />

After step 16 (IPP Post returns to Gateway), the internal model flow diverges:

[cols="1,2,2,3,3", options="header"]
|===
| Step | Pod | Namespace | What Happens | Debug Command

| 17-19
| EPP (ext_proc)
| _model namespace_
| Endpoint Picker selects optimal Prefill and Decode pods based on KV cache utilization and queue depth
| `oc logs -n <model-ns> deploy/<epp-deploy> -f`

| 20-21
| Sidecar
| _model namespace_
| Coordinates the Prefill/Decode transaction
| `oc logs -n <model-ns> <sidecar-pod> -f`

| 22-23
| Prefill Pod (vLLM)
| _model namespace_
| Processes input prompt, generates KV cache, returns KVXfer metadata
| `oc logs -n <model-ns> <prefill-pod> -c kserve-container -f`

| 24-25
| NIXL
| _model namespace_
| High-speed KV cache transfer from Prefill to Decode pod (GPU-direct RDMA or DCN)
| -

| 26-27
| Decode Pod (vLLM)
| _model namespace_
| Pulls KV cache via NIXL, generates tokens auto-regressively, streams response back to Gateway
| `oc logs -n <model-ns> <decode-pod> -c kserve-container -f`
|===

== Key Configuration Resources

++++
<div style="overflow-x:auto;max-width:100%">
<img src="_images/deepdive-crd-hierarchy.svg" alt="CRD relationship hierarchy" style="min-width:1750px;width:100%" />
</div>
++++

These are the ConfigMaps, Secrets, and CRDs that control the request flow:

[cols="2,2,3", options="header"]
|===
| Resource | Namespace | Purpose

| `ConfigMap/payload-processing-plugins`
| `openshift-ingress`
| Defines which plugins run in IPP pre and post stages

| `Secret` with label `inference.llm-d.ai/ipp-managed=true`
| _external-models namespace_
| Provider API keys for apikey-injection plugin (3.5 label; was `bbr-managed` in 3.4)

| `Config/default`
| _(cluster-scoped)_
| Platform anchor CR that triggers MaaS controller reconciliation

| `AITenant`
| `ai-tenants`
| Multi-tenancy configuration for the AI Gateway

| `MaaSModelRef`
| _model namespace_
| Maps user-facing model name to provider endpoint and target model ID

| `MaaSAuthPolicy`
| `models-as-a-service`
| Configures API key authentication via K8s Secret

| `MaaSSubscription`
| `models-as-a-service`
| Defines quota - associates user/team with allowed models and rate limits

| `ExternalProvider`
| _external-models namespace_
| Provider connection config (URL, auth type)

| `ExternalModel`
| _external-models namespace_
| Maps model name to provider and target model

| `AuthPolicy`
| `openshift-ingress`
| Generated by maas-controller from MaaSAuthPolicy

| `TokenRateLimitPolicy`
| _model namespace_
| Generated by maas-controller from MaaSSubscription
|===

[source,bash]
----
# View IPP plugin configuration
oc get cm payload-processing-plugins -n openshift-ingress -o yaml

# View provider secrets (check label)
oc get secrets -l inference.llm-d.ai/ipp-managed=true -A

# View all MaaS CRDs
oc get maasmodelref -A
oc get maasauthpolicy -A
oc get maassubscription -A
oc get externalmodel -A
oc get externalprovider -A

# View platform config
oc get config default -o yaml
oc get aitenant -A
----

== Common Debugging Scenarios

++++
<div style="overflow-x:auto;max-width:100%">
<img src="_images/deepdive-debugging.svg" alt="Debugging decision tree" style="min-width:1170px;width:100%" />
</div>
++++

=== 500 Error on External Model

The request reaches the provider but credential injection failed:

[source,bash]
----
# Check if the Secret has the correct label
oc get secrets -n <external-models-ns> -l inference.llm-d.ai/ipp-managed=true

# Check payload-processing logs for apikey-injection errors
oc logs -n openshift-ingress deploy/payload-processing | grep -i "apikey\|credential\|secret"

# Check ExternalModel CRD is correct
oc get externalmodel <model-name> -n <external-models-ns> -o yaml
----

=== 401 Unauthorized

The API key is invalid, expired, or revoked:

[source,bash]
----
# Check Authorino logs
oc logs -n kuadrant-system deploy/authorino | grep -i "denied\|reject\|invalid"

# Check MaaS API key validation
oc logs -n redhat-ai-gateway-infra deploy/maas-api | grep -i "validate\|invalid"

# Check MaaSAuthPolicy
oc get maasauthpolicy -A -o yaml
----

=== 429 Too Many Requests

Token quota exceeded:

[source,bash]
----
# Check Limitador logs
oc logs -n kuadrant-system deploy/limitador-limitador | grep -i "rate\|limit\|exceed"

# Check subscription limits
oc get maassubscription -A -o yaml | grep -A5 "rateLimits"

# Check TokenRateLimitPolicy
oc get tokenratelimitpolicy -A -o yaml
----

=== Model Not Found

The model name doesn't match any MaaSModelRef:

[source,bash]
----
# List all registered models
oc get maasmodelref -A

# Check payload-processing logs for resolver errors
oc logs -n openshift-ingress deploy/payload-processing | grep -i "resolver\|model.*not.*found"

# Check the pre-processing header extraction
oc logs -n openshift-ingress deploy/payload-pre-processing | grep -i "model\|header"
----

== RHOAI 3.4 vs 3.5 Differences

++++
<div style="overflow-x:auto;max-width:100%">
<img src="_images/deepdive-34-vs-35.svg" alt="RHOAI 3.4 vs 3.5 architecture comparison" style="min-width:700px;width:100%" />
</div>
++++

If you are debugging a 3.4 cluster, these are the key differences:

[cols="2,2,2", options="header"]
|===
| What | 3.4 | 3.5

| DSC component
| `kserve.modelsAsService`
| `aigateway.modelsAsAService`

| MaaS API namespace
| `redhat-ods-applications`
| `redhat-ai-gateway-infra`

| Secret label
| `inference.networking.k8s.io/bbr-managed=true`
| `inference.llm-d.ai/ipp-managed=true`

| Kuadrant integration
| EnvoyFilter-based Wasm
| WasmPlugin CRs

| External model CRD
| Single `ExternalModel`
| `ExternalProvider` + `ExternalModel`

| IPP architecture
| Single ext_proc stage (after auth)
| Two stages: pre (before auth) + post (after auth)

| IPP plugins (post)
| model-provider-resolver, body-field-to-header, api-translation, apikey-injection
| maas-headers-guard, stream-usage-enforcer, model-provider-resolver, api-translation, apikey-injection
|===
